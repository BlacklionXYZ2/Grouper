## 15:30 — Relay security fixes (nonce domain separation, login CSRF, cookies, sign-out, hub secret tag)

- **Agent:** Claude Code · Sonnet 5.5
- **Asked by:** the coordinator, after a security review of the merged relay.
- **Changed:**
  - `relay/src/index.ts`, `tokens.ts`, `google.ts`, `util.ts`, `account.ts`:
    - The Google `nonce` claim must now be `b64url(SHA-256("grouper-relay-v1:" + relay_nonce))`. Sign-in and claim bodies carry `relay_nonce`. The relay checks its HMAC, expiry and one-time use, and that the hash matches.
    - Browser sign-in is bound to the browser: `/relay/auth/start` sets `grouper_relay_state` and sends `state`. `/relay/auth/return` requires both to match and takes the relay nonce from the cookie.
    - Optional `RELAY_WEB_CLIENT_ID` makes browser sign-in use and require only that audience.
    - `/relay/v1/sign-in`, `/sign-out` and `/hubs/claim` require `application/json` (415) and a same-origin `Origin` when one is sent (403).
    - `Set-Cookie` for `grouper_relay` and `grouper_relay_state` is stripped from hub responses.
    - Sign-out everywhere closes the account's client sockets with 4401 and aborts in-flight requests and streams.
    - Hub secrets are now `hs.<acct>.<rand>.<tag>`; the Worker checks the tag before calling the Durable Object.
  - `relay/test/smoke.mjs`: new request shapes, and 37 new checks for each fix (109 total).
  - `scripts/relay-e2e.mjs`: passes `relay_nonce` and mints relay tokens with the hashed nonce; adds a raw-nonce replay check and a form-post check.
  - `crates/hub/src/relay.rs`: `POST /v1/relay/link` takes `relay_nonce` and forwards it to the relay's claim call. Tests updated.
  - `docs/relay-design.md`, `relay/README.md`, `relay/wrangler.toml`: describe all of the above.
- **Why:** a malicious hub could have used a relay nonce as its own hub nonce and replayed the victim's ID token to the relay (hub takeover or session), and browser sign-in could be forced into the attacker's account. Deviation from the brief: the state cookie is `SameSite=None; Secure` on HTTPS (`Lax` on plain HTTP), not `Lax`, because Google's `form_post` return is a cross-site POST and browsers don't send Lax cookies on one. The state value is unguessable and posted back, so it can't be used for CSRF.

One-time offer notification 20 s after launch when the hub is claimed and not linked (marker file `phone-access-offered`).
  - `apps/desktop/src-tauri/Cargo.lock` — picked up the hub crate's `tokio-tungstenite` dependency (the lock was stale since the relay connector landed; `--locked` failed before).
- **Why:** the relay is how phones and browsers reach the hub; owners need a way to turn it on without curl. Linking from the browser does the nonce and hash on the hub so the raw relay nonce never reaches the page, and a purpose on the existing `state` reuses the one return page registered with Google. Deviation from the brief: the browser doesn't call `POST /v1/relay/nonce` and hash with WebCrypto; `link/start` does both on the hub.
