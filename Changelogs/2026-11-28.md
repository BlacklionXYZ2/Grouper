## 10:00 — Windows and Mac builds on GitHub Releases

- **Agent:** Claude Code · claude-opus-5-5
- **Asked by:** Oscar: it wasn't clear where to get the Mac and Windows executables; make them GitHub releases.
- **Changed:**
  - `scripts/publish-release.sh` — new. Attaches a build to a release: a `v*` tag goes on that version's release; a push to `harness` or `main` goes on the rolling `<branch>-latest` pre-release, whose tag is moved to the newest commit. Each asset's label names its commit. Whichever workflow finishes first creates the release.
  - `.github/workflows/desktop.yml` — job gets `contents: write`; pushes of `v*` tags also build (path filters don't apply to tags, so `branches: ["**"]` was added to keep branch pushes); new last step uploads `Grouper-windows-x64-setup.exe`.
  - `.github/workflows/apple.yml` — same trigger and permission change; uploads `Grouper-macOS-arm64.zip` straight after packaging (before the iOS simulator build).
  - `README.md` — new "Download the apps" section: where the files are, what each is, and how to open the unsigned builds.
- **Why:** builds were only Actions artifacts, which need a sign-in, are buried in run pages and expire after 14 days. A rolling pre-release gives a fixed place with the newest build; tags give permanent versions. A separate release workflow (workflow_run) was rejected: it would add a third workflow to download artifacts the build jobs already have.
