## 00:30 — Windows app quit on launch

- **Agent:** Claude Code · claude-opus-5-5
- **Asked by:** Oscar: the Windows executable from the release doesn't run.
- **Changed:**
  - `apps/desktop/src-tauri/src/node.rs` — `NodeHandle::start_with_options` spawned the desktop node with a bare `tokio::spawn`. In "This computer" mode Tauri's synchronous setup hook calls it, where no Tokio runtime is current, so the app panicked ("there is no reactor running") right after starting its local hub and quit with no window. It now uses the current runtime if there is one, else Tauri's (`tauri::async_runtime::handle()`). New test `node_starts_outside_a_tokio_runtime` starts a node from a plain `#[test]`.
- **Why:** found by launching the installed `grouper-desktop.exe` with `RUST_LOG=info`: stderr showed the panic at `src\node.rs:174`. CI never launched the app, and the existing node test runs inside `#[tokio::test]`, so it had a runtime. "Another computer" mode starts its node from async code and wasn't affected.
- **Verified:** rebuilt release exe launched against the owner's existing install: stays up, window "Grouper" shown, local hub `/healthz` 200, node connected and its MCP servers loaded. Desktop `cargo test` 18 passed; `cargo clippy --all-targets -D warnings` clean.
