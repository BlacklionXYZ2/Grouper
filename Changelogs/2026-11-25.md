- **Changed:**
  - **Review fixes** (Gemini 4 Neon reviewed wave 1, then fixed its findings; I checked the diff):
    - A stored token was sent to whatever hub `--hub`/`GROUPER_HUB` named; now only to the hub it was saved for.
    - Thread shells get `GROUPER_THREAD_SHELL=1`, and the CLI refuses stored credentials when it's set.
    - The hub won't generate a new master key when the database already holds sealed keys (it used to, silently making every key unreadable); the key file is created atomically.
    - Anthropic stream block indexes are capped (a hostile index could overflow or exhaust memory).
    - Event subscribers that fall behind get the missed stored events replayed from the database instead of silently losing them (which could leave `grouper chat` waiting forever).
    - OpenAI-compatible streaming: empty tool arguments become `{}`, `"error": null` isn't an error, empty `finish_reason` ignored, tool calls without `index` split by id, thinking not duplicated.
    - A stream cut mid-event is a retryable network error, not a bad response.
    - The final text event comes before its usage line.
    - Memory: no panic when a memory is deleted concurrently; duplicate saves merge tags; the recall budget counts characters.
    - `grouper connect`'s default workspace uses the home folder on Windows; empty API keys no longer overwrite stored ones; the CLI reads keys without echo; the DPAPI buffer is zeroed.
  - **Usage and cost** (Codex): `crates/hub/src/usage.rs`, `crates/cli/src/usage.rs`. `GET /v1/usage` grouped by day, provider, model, conversation or thread; `grouper usage`; `grouper chat` ends with the conversation's total including the orchestrator. Cache pricing per provider kind, or the model's own `cache_read_price`/`cache_write_price`. OpenRouter and DeepSeek balance collectors (hourly and on demand), `grouper usage balances`, and a read-only `list_usage` tool for the orchestrator.
  - **Registry learning and skills** (Opus): `crates/hub/src/registry.rs`, `crates/hub/src/skills.rs`. Thread outcomes with task type, duration, cost and tokens; orchestrator grades (`grade_thread`) and user ratings (`grouper rate`); stats per model, device and task type; use-case proposals when stats shift (one pending per model, you accept or reject); priority rules (`grouper rules`, e.g. sensitive → local only) used to choose a thread's model, with the reason recorded; skills saved after successful tasks and offered as a `[Skills]` block on similar turns.
