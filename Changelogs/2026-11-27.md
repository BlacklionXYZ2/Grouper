## 06:07 — Package E: One install, one device

- **Agent:** Antigravity · Gemini 4 Neon
- **Asked by:** Implement Package E ("One install, one device"): stop one PC from showing up as separate hub, node (`<install_id>-node`), and admin rows; group rows per install in `GET /v1/devices/installs`; exclude the hub's own install from move targets.
- **Changed:**
  - `crates/hub/src/db.rs` — added `ensure_hub_device_for_install`, `device_install_id`, `legacy_node_install_id`, `canonical_install_id`, and `find_install_hub_candidate` so an embedded hub adopts or creates its host device row under the app's `install_id` (`NODE_INSTALL`), reuses it across restarts without bumping `epoch`, and migrates legacy unattached hub + `<install_id>-node` rows; added unit tests.
  - `crates/hub/src/host.rs` — added backwards-compatible `start_with_install` (keeping `start`, `start_paused`, `start_with_options`, and `Options` unchanged); added restart/grouping integration test.
  - `crates/hub/src/devices.rs` — normalized legacy `<install_id>-node` non-admin rows when grouping `GET /v1/devices/installs`, added `InstallDeviceRow` (`rows` field on `InstallDevice`) and `InstallDevicesResponse::move_targets()` excluding `is_hub` installs while preserving per-row device APIs; added integration test.
  - `apps/desktop/src-tauri/src/node.rs` — passed `settings.install_id` (instead of `node_install_id()`) to local and remote node registration, checked `device_install_id` when reusing a saved local node token, and extended the in-process node test.
  - `apps/desktop/src-tauri/src/main.rs` — updated both embedded hub startup call sites (`ensure_embedded_hub` and `.setup`) to call `hub::host::start_with_install` with `settings.install_id`.
- **Why:** Previously an embedded desktop hub created an unattached hub row (`install_id = NULL`), an admin row (`install_id`), and a node row (`<install_id>-node`), causing one PC to appear as three entries and offering its own node as a hub-move target. Sharing one `install_id` across the hub/node row and admin row aligns with the account → device ids → `hub_device_id` model while keeping the non-admin node / admin UI security boundary intact.
